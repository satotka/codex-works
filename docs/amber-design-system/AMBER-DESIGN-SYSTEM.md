# AMBER Design System

Version 1.1 · 2026-10-15 · 新作制作の参照用

## 1. この文書の使い方

AMBER POKER、AMBER BETWEEN、AMBER DERBYの実装から、シリーズの共通言語を整理したガイド。新作の企画・画面設計・実装・レビューで参照する。

### デザインシステムとしての位置づけ

[デジタル庁「デザインシステムとは」](https://design.digital.go.jp/dads/guidance/design-system/)を参考に、デザイン原則、情報と操作の設計、UI部品、アクセシビリティを含むガイドラインを結びつける。企画者・デザイナー・実装者が同じ体験を目指して判断するための共通資料とする。

AMBERにはシリーズ固有のブランドがあるため、[ローカルデザインシステムの説明](https://design.digital.go.jp/dads/guidance/local-design-system/)も参照し、世界観に合わせて定義する。本書は考え方を参考にしたAMBER独自の仕様であり、デジタル庁の部品・コードを導入済み、または同システムに準拠済みという意味ではない。

|構成|AMBERで定義する内容|参照章|
|---|---|---|
|デザイン原則|世界観、プレイヤーへの約束、判断の優先順位|2|
|情報設計|読む順序、状態・結果・金額の関係|4・7・9|
|基本デザイン|色、文字、余白、形状、奥行き|5|
|UIコンポーネント|部品の役割、状態、使う条件、操作|6|
|体験パターン|部品を組み合わせた選択・確定・回収・復帰|7・8・10|
|検証と運用|受入確認、例外、更新、改善の記録|11・12|

現在の資産は仕様文書と新作依頼のひな形。共通コードライブラリ、Figma部品、音源セットは未整備。既存実装は根拠と作例として参照し、再利用時は本書との差分を確認する。

判断では、操作と理解のしやすさを最初に確保し、その上でルールの正確さ、一貫性、演出を整える。世界観のために文字を小さくする、押下領域を削る、重要な状態を色だけにする変更は採用しない。数値は設計の起点であり、検証で問題があれば理由を記録して改善する。

**「実装で確認」**は既存作品に存在する特徴。**「共通基準」**は今後の作品で採用する規定。既存作品すべてがこの規定に適合していることを意味しない。世界観の言語化、統一値、操作原則には新しく整理した提案を含む。

調査対象はGitHub保存版の3作品。公開画面との一致、実機での操作感・音・視認性は未検証。特にBETWEENには旧選択フェーズのコードが残っているが、現在の説明と通常進行はDEAL後の自動判定。旧コードを新作のルールとして引き継がない。

制作時は本書を添付し、「AMBER共通基準に従う。ゲーム固有のルールは別仕様で定義する」と指定する。まず第2・4・6章で体験を設計し、最後に第12章で確認する。

## 2. 世界観と体験の約束

**AMBERは、暗いアーケードの中で琥珀色の光が灯る、小さな遊技筐体。プレイヤーの選択に手応えがあり、結果を読み取り、次の一手を自分で決められる。**

実装で確認：暗い外装、金色の見出し、奥まったモニター、メダルの数字、立体感のある決定ボタン。カードゲームと競馬で題材が違っても、筐体を操作する感覚が共通する。

共通基準：

- **静かな待機、明確な反応。** 待機中は画面を落ち着かせ、入力・選択・確定・結果の瞬間に光と動きを集中させる。
- **同じ場所に同じ意味。** 残高、状態、主操作、音設定を毎回探さなくてよい構成にする。
- **選ぶ→確定する→見る→受け取る。** 段階を表示し、今できる操作と次に起きることを示す。
- **結果を急かさない。** 結果を読み終える前に自動で次のゲームへ進めない。再挑戦は本人の操作で開始する。
- **題材の個性はプレイ面に。** カード、馬、盤面、専用の音は作品ごとに変え、外装・操作・数字の読み方はそろえる。

避ける表現：常時点滅する金色、画面全体を覆う光、無関係なネオン色の乱用、負けを責める言葉、ボタン位置が結果のたびに飛び変わる画面。

## 4. 画面の骨格

標準の読む順序は、**ブランド・設定 → 現在の状態 → プレイ対象 → 結果とメーター → 選択・BET → 主操作 → ガイド・履歴**。

```text
┌ AMBER TITLE                       GUIDE / SOUND ┐
│ ┌ 補助情報 ┐ ┌ 現在の状態・結果 ──────────────┐ │
│ │ 配当表等 │ │ カード／レース／盤面             │ │
│ │          │ │ CREDIT      WIN / LAST PAY       │ │
│ └──────────┘ │ BET・選択                        │ │
│              │ 補助アクション       主アクション│ │
│              └─────────────────────────────────┘ │
│ ガイド・遊び方・履歴・保存状態                    │
└──────────────────────────────────────────────────┘
```

共通基準：主操作は操作群の右側。回収や取り消しは左側。上下に並べる場合も読み順を維持する。二択はLEFT→RIGHT、LOW→HIGHの順。スマホで幅が足りない場合は押しやすさを優先し、無理に1行へ圧縮しない。

配当表や出走表は判断に使える位置に置く。カード系のスマホでは配当表を折りたたみ、進行中の対象・結果・主操作を優先。DERBYの出走表は投票の中心なので、補助情報として隠さない。

状態欄は「現在の段階」と「結果」の2行を予約する。長い日本語ガイドは別の領域に置き、GUIDEの切替でカードや主操作の位置を変えない。固定高を使う場合は文字拡大時に高さを解放する。

色だけで意味を伝えない。HOLD、選択済み、獲得、LOCKEDの文字・記号を併用する。上記の組合せすべてのコントラストを保証した表ではない。新作の実際の背景と文字サイズで、通常文字4.5:1、大きい文字3:1、操作境界とフォーカス3:1を受入基準として確認する。

外装には緩い陰影、モニターには内側の影、操作ボタンには下辺の厚みを使う。発光は選択と結果に限定する。背景模様を本文や数字の背後で強く見せない。

### 文字と数字

実装で確認：本文はArial / Yu Gothic / sans-serif。タイトルは太い大文字と広い字間。数字はCourier Newまたはmonospace。

共通基準：本文と操作ラベルは16pxを基本とし、本文の行間は1.6。補助12–13pxは重要でない装飾・重複情報に限定する。タイトルPC32–36px／スマホ22–25px、メーターPC28–32px／スマホ22–26px。8–10pxの既存装飾文字は新作の重要情報に使わない。[ローカルデザインシステムの文字サイズ基準](https://design.digital.go.jp/dads/guidance/local-design-system/)を参考にしたv1.1の変更。

数字は等幅、桁区切り付き。CREDITは残高、BETは賭ける額、WINはまだ回収していない額、PAID／LAST PAYは確定した払戻と定義する。作品ごとの会計仕様に合わせて「予約済み」「回収済み」を補足し、金額を二重に足したと誤解させない。

### 余白・形状

共通基準：余白は4 / 8 / 12 / 16 / 24 / 32px。外装半径18px、モニター12px、パネル8px、ボタン6px。PCの最大幅は1160pxを標準、DERBYの1180pxは例外として記録。スマホの外側余白8px、筐体内12pxを開始値とする。

カードは縦横比18:25、角丸8px。角の数字・スートと中央絵柄の領域を分け、重ねない。札の枚数や役判定はゲーム固有。新作では同じカード部品を参照し、POKERとBETWEENにある書体・絵柄の差を無意識に増やさない。

## 6. コンポーネントと状態

|部品|共通ルール|
|---|---|
|ブランド|`AMBER <ゲーム名>`、ゲーム名を琥珀色。題材の紋章は任意。スマホでは紋章を省略できる|
|主ボタン|金色、太い動詞、標準高さ60px／スマホ48px以上。常に現在の操作を表示|
|補助ボタン|暗い面＋明るい文字。主操作と同じ押下感。回収は安全に終える操作として明確に配置|
|BET調整|値を中央、減少を左、増加を右。MIN/MAXの意味・上限・予約方式は遊び方に明示|
|選択対象|琥珀色の枠＋面色または小さな移動＋選択ラベル。選択中とフォーカスを区別|
|メーター|ラベル＋等幅数字。未回収WINと確定した払戻を別の意味で表示|
|状態欄|短い段階名＋結果。通常更新は控えめに読み上げる|
|折りたたみ|44px以上の見出し、矢印で開閉状態を示す。配当表・遊び方に使用|
|SOUND / GUIDE|ヘッダー右、44×44px以上。ON/OFFを視覚とアクセシブル名の双方で示す|
|保存通知|フッターで通常状態。保存不能・別タブ競合は操作領域上部に理由と復帰操作|

ボタンの状態：

- 通常：役割に応じた面と輪郭。
- hover：輪郭または面を少し明るくする。タッチでも同じ情報を読めること。
- focus：3pxの明瞭な外枠＋4pxの間隔を標準にする。選択の金枠と混同しない。
- pressed：ボタンだけ2px沈む。周囲のレイアウトは移動しない。
- selected：色とラベルを持続させ、`aria-pressed`等で状態を伝える。
- disabled：灰色の面・文字・境界、影なし。重要なラベルまで透明にしない。押せない理由を近くの状態欄に表示する。
- busy：処理中の動詞を表示し再入力を防ぐ。ボタン領域を予約して消失させない。

既存には全体のopacityを下げる無効表示もある。新作ではBETWEENの主操作にある灰色表示を出発点に統一する。情報を読むだけのカードは無効ボタン扱いで薄くしない。

### 部品の使い分け

以下はAMBER独自の定義。部品はプレイヤーの目的と操作の意味から選ぶ。

|部品|使う場面|避ける使い方|
|---|---|---|
|主ボタン|段階を確定するDEAL・DRAW・レース開始|画面移動を実行ボタンにする。競合する主操作を複数置く|
|回収ボタン|未回収WINを確定して挑戦を終了|払戻済みの状態で再回収させる|
|トグル|音・ガイド等のON/OFF|DEAL等の一度の実行に使う|
|単一選択|馬・券種・投票枚数から一つ選ぶ|複数HOLDに使う|
|複数選択|カードのHOLDと解除|即時確定の二択と同じ説明にする|
|メーター|残高・BET・結果金額を読む|表示のみの値に押せる外観を与える|
|折りたたみ|任意に参照する配当表・遊び方|現在の結果や停止理由を隠す|
|状態通知|進行・結果・保存の通常報告|実況をすべて強い警告で読み上げる|
|警告＋復帰操作|操作停止の理由と復帰方法|敗北演出に警告の意味を流用する|

部品仕様は「目的／構成／表示値／状態／入力方法／アクセシビリティ／使用例／避ける例」を一組で管理する。例えば主ボタンは、動詞・実行可能か・処理中か・無効理由を受け取り、表示と押下反応を共通化する。BETの控除や配当判定はゲーム側で定義する。

## 7. 操作の共通文法

|段階|ユーザーに見せること|操作の扱い|
|---|---|---|
|準備|BET・候補・条件・開始可能か|設定を変更可能。必要条件不足なら主操作を無効化し理由を表示|
|選択|何を何個選ぶか、現在の選択|選択は即時表示。トグルは再操作で解除できる|
|確定・進行|何が確定したか、現在何が進んでいるか|BET・選択をロック。音設定は引き続き使える|
|結果|当否・役／順位・金額・次の選択|結果を保持し、回収／挑戦／次へを明示|
|回収・次へ|何枚獲得したか、次回の準備|会計を一度だけ反映して準備へ戻る|

すべてのゲームに全段階を強制しない。BETWEENの自動判定、DERBYのレース観戦など、ルールに必要な段階だけを採用する。

キーボード・クリック・タップは同じ状態遷移を使う。全操作をタップで完結できるようにする。カード系の基本キーはD／6＝主進行、A／4＝回収、W／8＝増加、S／2＝減少。選択中の1–5を優先する場合は4の競合を説明する。DERBY等へのキー導入は新規設計であり、既存にあると記載しない。

押しっぱなしでDEALや回収を連続実行しない。IME変換中・入力欄の編集・修飾キー付き操作を奪わない。Tabで移動し、標準ボタンはEnter／Spaceで起動できる。画面の主ボタン名とキー説明を常に一致させる。

## 8. 動き・音・手応え

実装で確認：POKERのHOLDは内容が8px下がり160msで移動、勝利の光は900ms、DOUBLEは1200ms、開閉矢印は180ms。BETWEENは短い電子音、DERBYは開始・実況段階・走行・結果に音がある。

共通基準：選択や開閉は120–180ms、カード公開や短い遷移は180–300ms、祝福は600–1200msを開始値とする。レース等のゲーム進行時間は作品固有。操作直後に視覚反応を返し、演出終了待ちで無関係な設定までロックしない。

HOLDの移動はスロット内に余白を予約する。勝利演出はプレイ対象の周囲に限定し、金額・主操作を隠さない。敗北は短く静かに表示し、強い点滅や警告音を使わない。

音は「選択＝短いクリック」「確定＝少し強い1音」「獲得＝上昇する短い音列」「失敗＝控えめな低い1音」を新作の共通語彙とする。初回はOFF、ユーザーがONにした後だけ再生し、設定を保存する。POKERの初期ONやDERBYの音設定非保存とは差があるため、これは今後の統一方針。

動きを減らす設定では発光アニメーションと移動を止め、枠・ラベルで状態を残す。レースでは結果と進行を文字でも示し、簡略演出／スキップ時にも判定と払戻を変えない。既存DERBYがこの要件を満たすことは未確認。

## 9. 言葉とガイド

英語の短いラベルは筐体の雰囲気に使い、日本語で意味と次の操作を説明する。GUIDE OFFは補足を隠す設定で、結果、エラー、押せない理由、金額の意味は残す。

|場面|文例|
|---|---|
|準備|BETを選び、DEALをタップ|
|選択|残すカードをタップ。もう一度タップすると解除|
|結果|未獲得WIN：200 ／ COLLECTで獲得|
|挑戦|DOUBLEで未獲得WIN全額を賭けて挑戦|
|獲得なし|獲得なし ／ BETを選び、もう一度DEAL|
|確定|200枚を獲得しました|
|保存不能|保存できません。この画面を閉じると進行状態が失われます|
|別タブ競合|別タブで更新されました。RELOADで最新状態を読み込んでください|

「惜しい」は根拠がある場面だけに使う。当たりやすさを誤認させる表現、回収より再挑戦を急かす表現を避ける。同値・引き分け・返却・再抽選は作品固有のルールとして必ず明記する。

## 10. スマホ・アクセシビリティ・復帰

共通基準：760px以下を基本の1列切替とし、実際の内容で調整する。DERBYの既存800pxは題材上の例外。320px幅・スマホ横向き・文字200%で、重要情報が欠けず操作できることを確認する。

押せる領域は44×44px以上。既存の細いBETボタンや35pxの取り消しボタンはそのまま標準化しない。幅が足りなければ2段化する。カードの枚数・位置関係を保ち、数字が読めなくなる縮小は避ける。

読み上げ用にカードの数字・スート、馬名・番号、選択、金額、結果を持たせる。Canvasの題名だけでなく、出走表・順位・払戻の文字情報を用意する。通常結果は`role=status`、操作停止等の重要通知は`role=alert`を使用し、実況の頻繁な読み上げは制御する。

画面上の配置と読み上げ順をそろえ、強制カラーモードでも境界・選択・フォーカスを判別できるようにする。リンクは下線等を併用する。今後デジタル庁の部品を採用する場合は、その部品で定められたフォーカスとアクセシビリティの仕組みを維持し、本書の独自指定で安易に上書きしない。

保存場所と復帰方針は遊び方に明記する。POKER・BETWEENは途中状態保存と競合停止がある一方、DERBYは中断した投票分を返す方式。新作では途中再開か返却かをルールに応じて選び、二重払戻を防ぎ、復帰時に何が起きたか表示する。保存失敗を自動保存成功として表示しない。

最初からやり直す操作は通常進行から離して遊び方等に置く。残高・未回収WIN・進行のどれが失われるか確認文に示す。音やガイドまで初期化する場合も説明する。

## 11. 作品ごとの拡張と更新

変えてよいもの：ゲーム対象、盤面、配当表、専用色、紋章、ルール、進行時間、題材固有の操作。

そろえるもの：暗い筐体＋琥珀色、ブランド書式、数字の意味、主操作の位置、選択の琥珀色、押下感、音とガイドの位置、結果を読む時間、復帰通知。

例外は新作仕様に「基準／変更／理由／他作品への影響」を記録する。本書の版と参照元コミットを新作の仕様書に残す。共通基準の変更は版を更新し、既存作品への適用は別作業として判断する。

### 制作と改善の流れ

1. 新作の利用場面と中心となる選択を定義する。
2. 原則から状態と情報の順序を設計する。
3. 基本デザインと部品を選び、操作パターンに組み合わせる。
4. 試作して初見の理解、入力反応、結果と金額の読み取りを確認する。
5. 受入チェックを行い、共通部品の問題か作品固有の問題か記録する。
6. 複数作品に有効な改善を本書へ戻し、適用する作品と時期を決める。

操作感の評価では、既存作と新作で「設定変更→開始→選択→結果→次へ」を試す。探し直した場所、誤操作、反応待ち、金額の誤解を記録する。

変更記録には、日付、対象、困っていたこと、変更、確認方法と結果、影響する作品、採用状態を残す。状態は「提案／試作／検証済み／採用／非推奨」。現行の共通基準は文書上の採用案で、操作評価済みとは扱わない。

版はAMBER独自に管理する。従来の使い方を変える変更は主版、互換性のある追加は副版、誤記修正は修正版を更新する。シリーズ全体の変更はユーザーが採否を判断し、制作担当者は差分と検証結果を提示する。

新作依頼のひな形：

> 添付のAMBER Design System v1.1を共通ガイドとして、AMBER ［ゲーム名］を作成する。世界観は暗い筐体と琥珀色の光。状態、プレイ対象、金額、主操作を安定した位置に置く。選択・確定・結果・回収を明確にし、タップとキーボードで同じ操作ができるようにする。ルールは［別仕様］に従い、共通ガイドとの差分は理由付きで記録する。受入確認は本書第12章に従う。

## 12. 新作の受入チェック

- [ ] ブランド、筐体、モニター、数字の書体がシリーズとして見える。
- [ ] 初見で現在の状態・選択対象・次の操作が分かる。
- [ ] 主操作と回収の位置が安定し、GUIDE切替でプレイ対象が動かない。
- [ ] 選択、フォーカス、成立役、無効、処理中を区別できる。
- [ ] CREDIT・BET・未回収WIN・確定払戻の変化を説明できる。
- [ ] 二択の順序と画面上のキー説明が一致している。
- [ ] タップ・マウス・キーボードで開始から終了まで遊べる。
- [ ] スマホ320px幅・横向き・文字200%で操作でき、44px以上の押下領域がある。
- [ ] 文字と操作境界のコントラスト、Tab移動、結果の読み上げを確認した。
- [ ] 音OFFと動きを減らす設定でも結果と選択が分かる。
- [ ] 結果演出が金額と操作を隠さず、本人の操作で次へ進む。
- [ ] 保存失敗、再読み込み、中断、別タブ競合で金額が壊れない。
- [ ] リセットの影響とゲーム固有の引き分けルールが明記されている。
- [ ] 本文・操作ラベルの基本16px、読み上げ順、強制カラーモード、リンクの識別を確認した。
- [ ] 既存作と新作を比較し、探し直し・誤操作・反応待ちを記録した。
